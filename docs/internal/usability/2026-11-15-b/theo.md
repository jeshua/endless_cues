# Theo: bench test

**Verdict: with-workarounds.** Every message I asked for arrived byte-for-byte as the screen said, the ramp ended on exactly 1.0, and the show file is clean JSON that diffs to one line. I would bench it further. What stops a plain yes: nothing in the app or the manual tells me it runs on Linux or Windows, a tested cue lost its patch when I added a second device, and a dead port looks exactly like a live one everywhere I looked.

Ratings: learn 4, speed 4, clarity 3, trust 3

## Tasks

- **bed**: done. File > Add Sounds made both cues; 'Whole sound' loop switch under Time & Loops; hear confirmed room tone still playing and 'looping' after 42 s of a 40 s file.
- **desk**: done. Settings > Network > Add a patch > ETC Eos family, then a Network cue with the 'Fire cue' command builder wrote /eos/cue/1/12/fire. The desk stand-in received exactly that, no arguments.
- **raw**: done-with-trouble. Typed message arrived as /composition/layers/1/clips/2/connect 1 with an int argument. But adding the Resolume patch un-patched the LX 12 cue I had just tested, and the Monitor does not show argument types.
- **ramp**: done. First try sent one bare message; the app warned 'A duration is set but the message has no #v# to fade'. With #v#: 126 float messages over 5.03 s (about every 34 ms), first 0.0, last exactly 1.0.
- **sensor**: done. OSC trigger is under 'More (2)' at the bottom of Basics, below the fold. Learn captured '/sensor/door 1'. door 1 and door 1.0 start heartbeat; door 0 does not.
- **buttons**: done. Settings > Modules > OSC control, one switch. /go, /cue/2/start and /panic all did what they say. I had to give heartbeat a number first; added sounds have none.
- **tally**: done-with-trouble. Show feedback needs a patch, so I made a Generic OSC one for 9100. GO sent /endlesscues/go, /cue/<n>/start, /running, /playhead. Choosing the patch also sent a stale /go, and a cue with no number is reported by an internal id.
- **tablet**: done. Web remote module: one switch, shows http://<ip>:8137/?k=<key>. curl got 200 text/html with the key, 403 without it or with a wrong one.
- **file**: done. Saves a folder 'The Cellar.ecshow' with show.json (139 lines, one field per line, relative media paths), media/ and versions/. Changing one port was a one-line diff. Yes, I would keep show.json in git.
- **wrong**: done. The app told me nothing. GO on the cue showed '→ /eos/cue/1/12/fire (ETC Eos family)' exactly as when it worked, and the patch's Test said 'sent (no answer heard)', the same words it used when the ping did arrive.

## Findings

- **Neither the app nor the manual says whether it runs on Linux or Windows** (major, missing, help): Searched the getting-started manual for 'Linux' and 'Windows': no mention. The menus I used are macOS ones (Show in Finder, ⌘ keys). I could not answer the question that brought me here.
- **Adding a second network patch un-patches every cue that was on 'the only patch'** (major, bug, network): With one patch the cue's Patch reads 'ETC Eos family (the only patch)' and it sends. After adding a second patch the same cue reads '— choose —', the row gets a ✕ and the footer says 'LX 12: no network patch chosen'. Nothing told me at the moment I added the patch; I only saw it because the footer count went up. Seen twice, in two shows.
- **A send to a dead port looks the same as a good one, and the patch status reads 'sent (no answer heard)' either way** (major, confusing, network): Port changed to 8099, GO: Network strip and Monitor show '→ /eos/cue/1/12/fire (ETC Eos family)', no port, row not marked. Test: 'sent (no answer heard)' with a grey dot. That is word for word what Test said earlier when my stand-in on 8001 did receive /eos/ping. The Resolume and Tally patches, which I never tested, show 'sent (no answer heard)' too. My stand-in does not answer pings, so I could not see what a real desk's answer looks like.
- **Monitor credits every incoming message to 'ETC Eos family'** (minor, confusing, network): /go, /panic, /cue/2/start and /sensor/door from the button box and sensor are all listed as '← ETC Eos family (127.0.0.1:52474)', and the Eos patch in Settings lists '← /sensor/window 1' as heard from the desk. On the bench everything is one IP, so it may be matching by address alone; on a real rig the button box would be another IP. Still, it took the first patch with that IP and said so with confidence.
- **Incoming messages that do nothing are logged the same as ones that fired a cue** (minor, missing, network): '/cue/99/start' (there is no cue 99) and '/sensor/window 1' (nothing listens for it) appear in the Monitor exactly like '/cue/2/start'. The OSC control chip says '4 received, last /cue/99/start'.
- **Monitor cuts the message off and never shows argument types** (minor, missing, network): The Monitor panel shows 'Resolume Arena /…  /composition/…': the address is cut and the argument is off the edge; the panel cannot be widened that I could find. The little Network strip beside the mixer shows more of the message than the Monitor does. Neither shows the type; I only know '1' went as an int because my listener said so. The Monitor's footer does explain the rule ('1 is an integer, 1.0 a float; force with f:1 i:1 s:1'), which is good.
- **With the Monitor open the cue toolbar loses Network, MIDI, Light, Wait, Memo and Mix** (minor, confusing, cue-list): With the Monitor panel open the toolbar ends at Disarm; the rest is cut off with no overflow sign. I thought I had added a cue and typed its name into nothing. Seen once.
- **Turning on Show feedback sends a GO that is not happening** (minor, confusing, network): The moment I chose the Tally patch, the display received '/endlesscues/go "" "room tone"' and '/endlesscues/playhead 2 heartbeat'. That GO had been pressed about a minute earlier. A tally that lights a 'GO' lamp would have flashed. Seen once; it may be meant as a state dump.
- **Show feedback names an unnumbered cue by an internal id, sends numbers as strings, and its messages are not listed anywhere** (polish, missing, network): Received '/endlesscues/cue/c_1589d340/start "room tone"' for a cue without a number, and '/endlesscues/go 2 heartbeat' with 2 as a string. The card only says 'GO, cues starting and stopping, the playhead'. I learned the protocol by reading my listener.
- **OSC trigger is hidden under 'More (2)' below the fold of Basics** (minor, confusing, inspector): Basics shows Number, Name, Notes, Colour, Flagged, Armed, waits, Continue. '▸ More (2)' only appears after scrolling the inspector, and the trigger fields after opening it. I found it only because Settings > Network mentions 'a cue's OSC trigger, under More in its Basics'.
- **Added sounds get no cue number, and their Name field is empty though the list shows a name** (polish, confusing, cue-list): room tone and heartbeat came in with a blank Number; /cue/<number>/start had nothing to address until I typed one. The inspector's Name field is empty while the row shows 'heartbeat' in grey. A Network cue added later in a fresh show did get number 1.
- **The show folder mixes what belongs in git with what does not** (polish, confusing, files): Beside show.json there is versions/ (a full copy of the show per save) and media/ (the wavs, copied in), and show.json holds the web remote key ('key': 'ccabf7c3'). All fine, but I would need a .gitignore for versions/ and media/ and to remember the key is in the history.
- **File > New Show goes to the start screen, and Revert to Saved does not ask** (polish, confusing, files): File > New Show showed the 'Endless Cues public alpha' start page with a 'New show' button to press again. File > Revert to Saved dropped two unsaved edits with no question (undo may bring them back; I did not try). Each seen once.
- **Device-aware patches: the Eos command builder wrote the right address and the bytes matched** (praise, praise, network): Choosing 'ETC Eos family' filled the port and printed where on the desk to turn OSC on. The cue offered Fire cue / GO / Stop / Macro / Submaster / Channel / Command line; 'Write the message' showed '/eos/cue/1/12/fire' before writing it, and exactly that arrived. Resolume has the same.
- **OSC fades are right: the app warns when #v# is missing, and the ramp ends on exactly 1.0** (praise, praise, network): 'A duration is set but the message has no #v# to fade.' in the inspector and '1 warning' in the footer. With #v#: 126 floats, evenly about 34 ms apart, 0.0 first, 1.0 last.
- **OSC trigger Learn captures the address and the argument, and matches on the argument** (praise, praise, network): Learn said 'Waiting on 53000… (cancel)', then filled '/sensor/door 1'. door 1 and 1.0 fire, door 0 does not. The port opened by itself.
- **OSC control, Web remote and Show feedback are one switch each, QLab-compatible, and say their state in the title bar** (praise, praise, settings): OSC control lists what it takes (/go · /panic · /stop · /cue/<number>/…) and shows 'listening on UDP 53000 · 4 received, last …' as a chip. The web remote refuses a request without its key (403).
- **The show file is plain, stable JSON: one changed port is a one-line diff** (praise, praise, files): show.json: 139 lines, one field per line, patches named once and referred to by id, media by relative path. diff between two saves: '<  "port": 8001,' / '>  "port": 8099,'. The version note wrote itself: 'network.patches.0.port 8099'. Saving back to the same content did not add a third version file.
- **Broken and warned cues are counted in the footer with the reason** (praise, praise, cue-list): '✕ 1 broken' with 'LX 12: no network patch chosen' is how I caught the un-patched cue.
